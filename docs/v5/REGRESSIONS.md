# Baseline regressions for the new V5

These checks carry forward three failures from `v5-signal-field-before-rebuild` (`abb86ca`). The diagnoses were verified in desktop Chrome at 1440 × 900 against the local production baseline. Temporary browser instrumentation recorded computed style, DOM removal and scroll calls. The existing mobile, reduced-motion and direct-load captures supply the other baseline observations.

## 1. Profile quote loses contrast in dark mode

The Home profile note sets its pink paper to `#f7bdc4` and the inset's text to permanent print ink `#201d28`. The intended quote rule asks the quote to inherit that ink. The broad `.signal-profile-grid > div > p:not(.signal-label)` rule has specificity `(0,2,2)` and beats the later `.signal-profile-inset .signal-handwriting` rule at `(0,2,0)`. As a result, the quote resolves `--signal-muted` against the pink surface. Light mode gives `#535670` against the pink at 4.44:1. Dark mode resolves `#c4c7e4` against the same pink at 1.03:1. A temporary scoped browser style that restored inherited ink gave 10.28:1 on the same paper in dark mode. [Profile markup](../../src/components/v5/HomeFeatures.jsx#L59) · [Broad selector](../../src/v5.css#L160) · [Dark token](../../src/v5.css#L293) · [Note styles](../../src/print-motion.css#L179) · [Baseline geometry](evidence/baseline/checks/v5-geometry.json) · [Dark mobile capture](evidence/baseline/checks/v5-390-dark-about-me.jpg)

**Shared code to watch.** Old profile grid selectors and global theme-muted text can carry this failure into any fixed-colour paper, label or screenshot annotation. Keep ink and surface paired at the material level and verify their actual computed colours in both themes.

**Regression check.** At desktop and mobile widths, check both themes on the settled note and at any transition position where the quote is meant to be readable. Require at least 4.5:1 for normal text or 3:1 for text that meets the WCAG large-text threshold. Check the arrow or other meaningful mark against the same paper. Toggle the theme while the note is visible and confirm readability holds.

## 2. Work filter throws when the featured strip is pinned

The Work page conditionally renders a gallery only when a category contains more than one featured project. It also sets the gallery's React key to the category. Changing All to Computer Vision removes the gallery because the destination has no qualifying group. Changing between categories that both show a gallery can also replace the host via its key. At desktop widths with motion enabled, `WorkGallery` sets `pin: true` on the React-owned `.signal-gallery`. ScrollTrigger creates a `.pin-spacer` and reparents the gallery into it. React still tracks the gallery as a direct child of `.signal-work-index`, and `media.revert()` is a passive effect cleanup. [Gallery eligibility and key](../../src/pages/Work.jsx#L14) · [Pin and cleanup](../../src/components/v5/WorkGallery.jsx#L33)

The failing filter click reached native `removeChild` with `.signal-work-index` as the receiver and `.signal-gallery` as the argument. The argument's actual parent was `DIV.pin-spacer`. The invalid removal reached the error boundary, and ScrollTrigger removed the spacer in cleanup after the failed removal. The same filtered URL loaded directly, desktop reduced motion and mobile touch each produced one project without error. Those paths either begin with no gallery or skip desktop pinning. [Desktop error capture](evidence/baseline/checks/v5-work-filter-desktop-filter-first.jpg) · [Baseline results](evidence/baseline/checks/work-filter.json)

**Shared code to watch.** Inspect any ScrollTrigger pin, custom spacer or other animation that changes a host's DOM parent. Filtered lists, keys, route transitions and responsive breakpoint changes can remove hosts. Keep ownership of host structure with React. Where an animation must move a host, verify it has returned to the expected parent before the deletion commit. Native CSS sticky with a stable structure is another option for this pattern.

**Regression check.** With desktop motion enabled, change All to Computer Vision before the gallery starts and again after advancing through the pinned gallery. Assert the selected category, URL query and one visible result, and observe zero `pageerror` events and no error-boundary screen. Then test All to Featured, back to All, rapid category changes, route departure while pinned and a resize across the breakpoint. Confirm no orphan spacers or duplicate triggers. Repeat the basic category change with touch, keyboard and reduced motion, and open the direct filtered URL.

## 3. Browser Back restores Home selection and then resets its scroll

`Home` records the project slug in the current history entry through a query update with `replace: true`. Back therefore recovers `/?project=packetlark`. The shared `App` tree uses `BrowserRouter`, keys `RouteContent` by path under `AnimatePresence mode="wait"` and remounts the wrapper on a path change. Its layout effect calls `window.scrollTo(0, 0)` on every hashless mount. It has no branch for back/forward navigation and no restoration per history entry. The project picker’s `preventScrollReset` flag leaves this custom effect untouched. The separate route-focus effect calls `focus({ preventScroll: true })`. [Router setup](../../src/main.jsx#L12) · [Route scroll effect](../../src/App.jsx#L41) · [Route transition and focus](../../src/App.jsx#L80) · [Project query](../../src/pages/Home.jsx#L109)

Chrome reported `history.scrollRestoration === "auto"`. The tested trip left Home at `781 px`. On Back, after the browser restored that offset, the app's layout-effect call was observed entering `scrollTo(0, 0)` from `781 px` on `/?project=packetlark`. It finished at `0 px` with the project query and route-container focus intact. [Baseline interaction log](evidence/baseline/checks/interactions.json)

**Shared code to watch.** The scroll reset is owned by the shared route wrapper and can propagate to every route if inherited. Account for the location key and navigation type in restoration. Coordinate application scroll restoration with the browser, asynchronous route mounts, layout changes and hash-target resolution. Keep focus handling independent of scroll position.

**Regression check.** On Home, select PacketLark, scroll it to a measurable reading position on a hashless URL and open Work. After Back, assert the URL, selected project and prior offset after the route transition and relevant layout settle. Forward should restore the Work history entry. Repeat with two positions on separate entries for the same path and with reduced motion. Verify that fresh navigation starts at the intended route entry and direct `/#work` or lazy article-heading links still reach their target.
