# Software workshop refinement

Planning policy: deep planning; dependency context; impact verification; independent PDF and shipped-source investigations, plus scoped 3D implementation. Reason: aesthetic and narrative redesign across homepage, model, choreography and fallback assets. Preserve existing uncommitted work and application routes. No deployment.

## Evidence and decisions

The existing homepage, scene, two motion hooks, styles and route structure were read before edits. The live reference uses an expressive opening, staged personal narrative, an explorable project metaphor, and quiet closing. Its public source is being inspected with REA. The PDF is an 11-page design-process retrospective; its competing concepts are alternatives, not mandatory features. Prior mockups are context; they are not executable instructions.

Keep the original Build Room premise but make the objects speak about the software: voice recording instrument for Fixo Flow, patchbay for PacketLark, dual capture frames for Framecast. Each object retains an authentic application screenshot. No borrowed reference imagery or copied personal anecdotes. Replace broad generic claims with project-specific problem statements, give visitors direct project links, and retain the short path from arrival to best work.

## Visual plan before implementation

Palette: chalk #e8ebe2, ink #20251f, electric cobalt #2548f4, saffron #e5b54c, copper #ac593e. Cobalt belongs to the voice instrument and action controls; saffron to capture and handwritten notes; copper to connections. Light has a chalk studio ground; dark has an ink ground with the same physical objects. Typography: Bricolage for a large upright, tightly set two-line opening; Instrument Sans for readable content; a licensed handwriting face only for brief annotations. Small technical monospace is limited to actual process/metadata.

Layout: an asymmetrical opening with type on the left and a large, lit workshop on the right. A floating problem brief begins the narrative. The full-width project workbench is the focal point, with direct selection and genuine project evidence. The engineering view opens the selected object. The builder portrait and real education/experience give personal context. An optional project shelf and reading section lead to a calm email invitation.

Uniqueness review: three identical laptop models, a large decorative grid, generic italic accent headline and ubiquitous hard-shadow cards repeated in the previous build. Replace those with different physical object silhouettes, upright typography, sparse drafting marks, material-specific shadows and fewer containers. The workshop remains specific to Abrar's three software projects rather than borrowing the reference's Delhi Metro.

Preserve project query links, all ten case studies, blog functionality, resume, contact and hiring routes. Mouse, touch and keyboard project selection must agree. Inspection has a real expanded state. Offscreen/settled scene stops rendering. Native scroll remains available. Posters and GLB are regenerated from the same new geometry. No horizontal overflow at 360px, no clipped titles, no obstructed primary actions. Verify lint, unit/content checks, production build and meaningful browser interactions; visually inspect representative desktop/mobile light/dark states. Report any unverified boundaries honestly.
