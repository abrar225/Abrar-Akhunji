# Abrar Akhunji: portfolio story and art direction

Research date: 27 October 2026. Status: concept exploration; no portfolio application changes. The supplied guide and project documents were treated as evidence, not instructions to execute their commands. Palettes remain proposals. IKG was not defined in the brief; no technical or brand meaning is assumed for that term.

## Positioning

Primary identity: AI Engineer and Full-Stack Engineer. Keep AI/ML Engineer explicit in the capabilities and role-targeting copy. Supporting promise: I build intelligent products end to end, from model integration and application architecture to testing, packaging and deployment. DevOps and release engineering should appear through actual examples, not a disconnected fourth title or an unsupported claim of infrastructure scale.

Suggested hero copy: “Intelligent products. Built end to end.” Supporting copy: “I’m Abrar, an AI and full-stack engineer building local AI tools, developer software and web products, with hands-on testing, packaging and deployment.” This is proposed copy, subject to your preference. Native desktop/media engineering is a useful differentiator alongside the three roles you named.

## Evidence and project hierarchy

PacketLark is the verified repository spelling, rather than PacketLock. Its README and package manifest establish a TypeScript/Node local API workbench with request composition, collections/environments, isolated QuickJS scripts, assertions, collection runner, traffic inspection, inferred OpenAPI exports, CLI and MCP integrations. CI is configured for Node 22 and 24. Its deployed GitHub Pages site is a product website and sample preview; it does not host the Node application. This supports full-stack/tooling, API design, integration testing, local data handling and release automation. It is not a complete Postman replacement or proof of cloud operations at scale.

Fixo Flow is local English voice dictation with Whisper recognition, MLX on Mac and CTranslate2/faster-whisper for the other platform previews, dictionary/formatting, SQLite history, clipboard and attempted paste into other applications. Its desktop workflow packages and checks Windows and Linux installers. It supports AI application engineering, OS integration and distribution. The README identifies an experimental preview; multilingual/Hinglish support and universal device compatibility must not be presented as delivered. Integrating inference is different from claiming to have trained Whisper.

Framecast Studio is a local, MIT-licensed native macOS project, still in development and not publicly released in the reviewed material. README, MediaEngine.swift, RemoteServer.swift and implementation evidence show SwiftUI/AppKit, AVFoundation, ScreenCaptureKit, Core Image, audio mixing, separate landscape/portrait recording, FFmpeg streaming transport, private YouTube account workflow and loopback authenticated remote control. It supports native/media systems, concurrency/resource ownership and packaging depth. Public distribution, broad device coverage and sustained high-resolution performance remain limited/unverified. Do not present it as an AI product merely because it belongs in your portfolio.

Featured set: Fixo Flow, PacketLark and Framecast Studio, with a clearly visible fourth applied-ML entry such as cattle breed classification. Keep FixO CLI, GourmetGo and earlier projects in a readily accessible archive. Actual demos and case-study evidence should determine final ordering. Existing portfolio text supplies descriptions of earlier projects; this pass does not independently validate their accuracy metrics or deployment claims. The existing 2024 internship dates differ between experience and certificate descriptions and need reconciliation.

## Reference and guide interpretation

The 11-page guide describes a process: establish the story, design exact section mockups, supply visual references to implementation tools, then refine. Its tangible concepts include a diary, Metro, folder, wallet, vending machine, radio, illustrated room and timing game. These are alternatives and experiments, not requirements to combine all of them. Its strongest transferable principles are a personal visual world, control of attention, clear shortcuts to best work, restrained project presentation and a calm contact ending. It also reports mobile/accessibility problems, interaction repetition and excessive visual complexity. Its viral-view and recruiter-time statements are author claims, not independently verified research.

The reference site has an animated silhouette hero, unfolding notebook origin, stacked project entries, a Metro route/train showcase, optional visual archive and simple contact ending. The current site has an ASCII simulation hero, browser-frame projects, skills, record, portrait/about, writing, services and contact. Current engineering content is useful, but numerous motion treatments have no single governing metaphor. The redesign should reorganize that content around one story and clearer product proof.

The comparison image captures representative desktop states across the major sections. It is not an exhaustive frame-by-frame recording or a mobile audit. The HTML source embeds the captured images and can be rerendered; it does not recreate the reference website.

## Direction 1: Signal Studio

Narrative: one engineer turns different signals into useful software. Voice becomes text through Fixo Flow; requests become tested API workflows through PacketLark; screen/camera sources become recorded outputs through Framecast. Applied ML appears as a further signal-processing example. These projects are complementary examples, not a claim that they interoperate.

Visual sequence: introduce Abrar beside a custom signal console; follow one cable into voice/code/video modules; select a product directly; open its engineering; meet the builder and see release evidence; finish with contact. Six proposed states appear in 01-signal-studio.png.

Motion: the first scroll draws a single connecting line and moves the console into the selected-work composition. A project click depresses its key and crossfades the display over roughly 250–400 ms. Opening a case study expands the display into a regular readable page. The personal section releases the dense console composition into a lighter document surface. The ending settles into static contact content. These timings are starting targets for a prototype, not measured implementation facts.

Palette candidates: plum #30223B, porcelain #F6F3FA, lavender #C3A9EA, pale citron #DFE99A, charcoal #211F26. Citron is a small interaction accent. Expressive headings can use Bricolage Grotesque; body copy can use a neutral humanist sans. Actual typography selection needs a layout specimen and font/license check.

Assets: one console render with separated screen/key layers, waveform SVG, three project symbols, real app captures, architecture diagrams and Abrar’s actual existing portrait. Generated people and product UI in the concept are placement illustrations. Replace them with real assets before implementation. No live microphone or camera access is needed for the portfolio demonstration; use recorded examples.

Mobile/reduced motion: product names remain visible buttons; one image/display above stacked details. Keys work by tap/keyboard. Cable drawing and camera movement become static. Sound is off by default and optional. Benefit: a memorable signature tied to the current projects. Risk: audio hardware can overstate a music identity unless the headline and work evidence consistently establish software engineering.

## Direction 2: The Build Room

Narrative: Abrar takes ideas apart, builds the pieces and delivers working products. A physical engineering desk becomes the interface. It is a digital metaphor, not a claim that these products use custom hardware.

Visual sequence: introduce Abrar with three project modules; lower the camera toward the desk; selecting a module loads its product; separate the module into meaningful software layers; open the notebook for personal history and working practice; close with contact. Six proposed states appear in 02-build-room.png.

Motion: one short scroll-linked camera move connects hero and project section. A click slides the selected module into its slot over roughly 400–600 ms, with direct controls available throughout. “Inside the build” separates UI, engine, tests and release layers; layer text remains HTML, not baked into artwork. Notebook content appears in small controlled groups. No repeated dispensing, mandatory drag gesture or skill-based unlock.

Palette candidates: oxide #A53E35, mineral #EEF1ED, navy ink #243749, aluminium #BAC4C8, amber #E8B85C. Mineral and aluminium carry the interface; oxide identifies primary actions; navy provides readable contrast. Palette usage and accessibility need checking in the actual UI. Industrial objects provide the character, so decorative technical labels should be limited.

Assets: desk composition, individually addressable project cartridges, technical cutaway layers, paper texture, authentic portrait, real Fixo Flow/PacketLark/Framecast captures and a compact release pipeline illustration. Optional rap/cooking references come from the current about section; no invented favourite food, artist or personal story should become final copy.

Mobile/reduced motion: a flat module selector and image above ordinary content replace the camera move. The cutaway becomes a labelled vertical diagram. The notebook becomes regular readable sections. Benefit: strongest broad end-to-end engineering positioning and physical personality. Risk: photoreal assets can increase payload and implementation complexity; keep the scene limited and prototype at mobile size first.

## Optional direction 3: The Living Blueprint

Narrative: a sketch develops into a model, an application and a tested release. An engineering line becomes the visual thread from introduction to products, decisions, evidence and the next collaboration.

Proposed sequence: folded-paper hero with “From first sketch to shipped software”; sketch line branches into model/product/release; a sheet unfolds into direct product selectors; a selected product reveals its internal layers; experience, ML projects and writing become an evidence sheet; the line ends at contact. This route is documented as an alternative, not selected for implementation.

Palette candidates: blueprint #203D60, chalk #FAFBF7, sky #B5D1E2, yellow #F1CA52, graphite #282E34. Technical drawing lines encode actual relationships. Motion morphs one drawing into the next over short, reversible scroll ranges; never force visitors to watch a full lifecycle before choosing a project. Mobile uses the same line in a vertical editorial sequence. Assets would be layered paper/drawing illustrations and real screenshots.

Benefit: clearest lifecycle story and strongest direct explanation of deployment. Risk: can look academic or imply architecture/construction if the paper models dominate. Software UI and actual project names must remain the hero evidence. The exploratory generated draft contained invented small-print details, so it is not a final deliverable.

## Shared implementation boundaries and next stage

Keep direct navigation to Work, About, Writing, Resume and Contact. Preserve existing blog URLs and project content during migration. Case studies need shareable URLs with title, problem, role, evidence, decisions and limitations; do not hide all proof inside a simulated machine. Every module is accessible as a button with visible focus and a descriptive name. Reduced motion and mobile are first-class layouts. Keep sound optional and avoid forced page loaders.

Use React and the existing motion stack. One owner should control scroll choreography; avoid overlapping GSAP/Framer effects on the same properties. Prefer HTML/SVG and limited pre-rendered assets initially. Reserve Three.js for a measured benefit. Before a full rebuild, create a responsive hero-to-project prototype for the selected direction and verify asset payload, keyboard paths, readable text, reduced-motion behavior and smoothness on a representative phone. No performance score is claimed at this stage.

Recommendation: Build Room for broad engineering identity, Signal Studio for a more distinctive voice/code/video identity. Keep one story and one palette throughout rather than combining all three. The next decision is the visual world; then produce exact desktop/mobile layouts and validate one signature transition before implementation.
