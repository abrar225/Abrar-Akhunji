# Refreshing the contribution snapshot

The portfolio reads `src/data/github-contributions.json` at build time. Run `node scripts/fetch-github.mjs` from the repository to refresh `abrar225`, or pass another username as the single optional argument. Node 22 needs no installed packages. If `GH_TOKEN` or `GITHUB_TOKEN` exists, the script sends a query directly to the constant `https://api.github.com/graphql` endpoint. Otherwise it uses the already authenticated GitHub CLI through `gh api graphql`. Tokens remain in the process environment and are never printed or written into the snapshot.

The query requests only the profile login/URL and aggregate contribution-calendar fields. It does not request repositories, issue/PR details, private project names or private content. GitHub's calendar may include anonymized aggregate activity according to that profile's public settings. Label the visualization "contributions": this calendar is broader than commits alone. The [official ContributionCalendar schema](https://docs.github.com/en/graphql/reference/users#contributioncalendar) defines the source fields.

Validation rejects malformed responses, API errors, unknown users, unordered or duplicate dates, nonexistent UTC dates, mismatched weekdays, negative or non-integer counts, and unknown contribution levels. The enum maps exactly to levels 0–4. `totalContributions` preserves GitHub's reported total; `dailyTotalContributions` independently records the sum of returned days. If those differ, both remain intact: the script never rescales or invents daily counts to force agreement. A complete validated JSON file is written beside the destination and atomically renamed. Network, authentication, parsing or validation failure leaves the last good snapshot untouched.

The workflow supports a daily run at 02:17 UTC (07:47 Asia/Kolkata) and a manual run. It checks out the repository's default branch, refreshes the one JSON file and commits only that path when changed. It requests `contents:write` for that commit; it does not install dependencies or deploy the website. [GitHub documents](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) that scheduled workflows run from the default branch and can be delayed, so this is a daily refresh attempt rather than an exact-time guarantee.

The workflow first attempts the public query with its automatic `GITHUB_TOKEN`. Whether this repository-scoped token can access all requested user-calendar fields must be confirmed by an actual Actions run. If GitHub rejects it as inaccessible, create an optional repository Actions secret named `CONTRIBUTIONS_TOKEN` containing a personal access token that can read this public GraphQL profile. A classic token needs no private-repository `repo` scope for this public query. Configure it under the repository's Settings → Secrets and variables → Actions → New repository secret. The workflow passes that secret to the read step while checkout/push continue using the automatic repository token. GitHub's [authentication guide](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token) explains the automatic token and when an additional token is needed. Do not put tokens into source files. If branch protection blocks the bot's commit, leave protection intact and refresh through the normal reviewed change workflow.

This change only prepares local source and workflow files. No workflow was enabled remotely, no secret or account setting was created, no commit was pushed, and no Actions execution has been verified. GitHub documents that a commit made with `GITHUB_TOKEN` generally does not trigger another workflow, so a bot refresh alone should not be assumed to rebuild or deploy the production site. The normal deployment process must consume the new snapshot separately.

Local verification on 28 October 2026 used the existing authenticated CLI against the actual API. The response contained 368 days, from 26 October 2025 through 28 October 2026, with a reported total and summed daily count of 3,081. Its maximum day was 176 contributions on 8 August 2026. These are a dated snapshot, not a lifetime count or a promise about future results. CI authentication and its commit/push path remain unexecuted.

Focused local checks rejected ten malformed-response variants, preserved differing reported/daily totals without altering individual days, retained the previous file after an invalid request, and confirmed that a malformed token fails without printing its contents. Node syntax checking and the repository's ESLint check passed for the script. The workflow YAML was parsed locally; no GitHub runner or remote commit was executed.
